# Experimental and Implementation Decisions

Record material choices that the specification intentionally leaves open.

| Decision ID | Topic | Selected policy | Alternatives considered | Rationale | Tests affected | Date |
|---|---|---|---|---|---|---|
| DEC-001 | Tie policy | Identify near/exact ties with the BASE-005 band (`M > +ε → Q+`, `M < -ε → Q-`, otherwise `Q_tie`), then **merge `Q_tie` into `Q-`** for all conditional metrics and denominators. Always report `n_q_tie` (pre-merge count). Config value: `tie_policy="merge_into_q_minus"`. Exact `ε` is still open (must be explicit in config when BASE-005 is implemented). | (A) exclude `Q_tie` from conditional metrics; (B) keep a separate `Q⁰`/`Q_tie` denominator; (C) merge into `Q-` (selected) | Keeps resistance/recovery denominators defined without dropping borderline questions; matches the user's freeze for the initial study | CFG-006, BASE-005, SCORE-003, METRIC-010, SAE-009, MC-002 | 2026-07-25 |
| DEC-002 | Behavioral weight normalization | Require `w_r >= 0`, `w_u >= 0`, and exact `w_r + w_u == 1` | Allow unnormalized weights and log their sum | Spec recommended contract for CFG-003; keeps objective mixing unambiguous | CFG-003 | 2026-07-24 |
| DEC-003 | Unresolved experiment policies | Must be explicit constructor fields with no defaults; `None` forbidden. Tie disposition is frozen by DEC-001; RO manifest selection is frozen by DEC-009; continuation strings/EOS are frozen by DEC-010; multi-token scoring is frozen by DEC-011; invalid-row and tie-band `ε` remain open | Hidden defaults in code | CFG-006 forbids silent defaults; concrete values freeze via numbered DEC rows | CFG-006, SCORE-011 | 2026-07-24 |
| DEC-004 | Question content normalization / leakage hash | Identity normalizer: NFKC → strip → collapse whitespace → strip trailing `.!?` → casefold. Content hash = SHA-256 hex digest of UTF-8 normalized text. Leakage = same hash under more than one split (distinct `question_id`s allowed). Aligns with legacy `normalize_identity` / `question_norm`. | (A) lighter strip-only; (B) prompt-style normalizer that appends `.` | Matches existing TruthfulQA ETL identity joins and ID derivation; catches duplicate text under different IDs across splits | DATA-004 | 2026-07-28 |
| DEC-005 | Shared CB/IB belief provenance | Cross-polarity reuse of a `belief_variant_id` is allowed only when an explicit shared-provenance record `{question_id, belief_variant_id}` is supplied to the validator. Absent that record, CB↔IB reuse is a `DataIntegrityError`. Null `belief_variant_id` (neutral) is excluded from uniqueness and cross-polarity checks. | (A) forbid all CB↔IB reuse unconditionally; (B) allow reuse via a boolean flag on rows | Spec requires an explicit shared-provenance record for the exception path; a typed table keeps the allow-list auditable | DATA-006 | 2026-07-28 |
| DEC-006 | Neutral cardinality and order-regime mapping | Map `answer_order` `true-first`→`CF`, `false-first`→`IF` (accept `order_regime` `CF`/`IF` directly). DATA-005 applies to CF/IF only until RO artifacts exist. “Exactly one neutral” means exactly one distinct `neutral_prompt_hash` per `(question_id, order_regime, format)` among emitted rows for that key; repeated rows with the same hash are allowed. Scope: keys present in the format table under test (do not invent neutrals for absent questions). Neutral-template versioning is not enabled. | (A) count raw neutral rows; (B) require RO neutrals now; (C) allow multi-hash versioning by default | Matches current pair-bookkeeping duplicates; avoids inventing RO policy (DEC-003); keeps cardinality semantic rather than row-count based | DATA-005 | 2026-07-28 |
| DEC-007 | Question-macro weight field | \(w_{q,b}\) is `pair_weight` within the belief-pair / variant component for each `question_id`. Require \(\sum_b w_{q,b} = 1\) with absolute tolerance `1e-9`. Do **not** treat `condition_weight` as this summand. | (A) use `condition_weight`; (B) use `question_weight` | Current belief-triple artifacts already satisfy \(\sum\) `pair_weight` \(= 1\); `condition_weight` does not and would silently break the macro invariant | DATA-008 | 2026-07-28 |
| DEC-008 | Dataset manifest required reproducibility keys | Required keys (all must be present and non-`None`): `source_file_hashes` (non-empty mapping of source label → SHA-256 hex), `preprocessing_version` (non-empty str), `split_seed` (int), `ro_seed` (int; required even before RO rows exist), `belief_generation_provenance` (non-empty str), `prompt_template_version` (non-empty str). Incomplete or null-valued manifests raise `ManifestMismatchError`. | (A) omit `ro_seed` until RO exists; (B) reuse legacy `split_summary.json` key names only | Spec lists RO seed as required reproducibility metadata; keeping `ro_seed` explicit avoids a silent gap before PROMPT-phase RO work | DATA-009 | 2026-07-28 |
| DEC-009 | RO manifest selection and assignment | `ro_manifest_selection="primary_single"`: one primary RO manifest from dataset `ro_seed`; extra seeds only for sensitivity (PROMPT-006), not primary analysis. `order_manifest_id = f"ro:primary:{ro_seed}"`. Assignment: `digest = SHA-256(f"{ro_seed}\\0{question_id}")`; LSB of first byte 0 → CF-like (`truthful_label="A"`), else IF-like (`truthful_label="B"`). Lookup by `question_id` only (shared across N/CB/IB and optimizer trials). | (A) multi_fixed first-class RO axes; (B) process-global RNG; (C) average CF/IF into RO | Matches CFG placeholder and single `ro_seed` (DEC-008); deterministic cross-platform; PROMPT-004/005/006 | PROMPT-004, PROMPT-005, PROMPT-006, CFG-006 | 2026-07-28 |
| DEC-010 | MC0 continuation-string / tokenizer contract | Continuations are exact `"A"` and `"B"` (no leading space). No trailing newline on the continuation. Do not append EOS to scored continuation tokens. Chat-template suffix belongs to the rendered prompt / `prompt_template_version`, not the continuation. Config: explicit `continuation_A`, `continuation_B`, `continuation_include_eos` (no defaults; `None` forbidden). Phase B unit pin: `tokenizer_name="epistemic_sycophancy.ascii_letter"`, `tokenizer_revision="v1"` (deterministic local vocab; token IDs are Unicode code points). REAL-001 will pin the experiment model tokenizer later without changing these strings. | (A) leading-space `" A"`/`" B"`; (B) append EOS; (C) require HF tokenizer in every unit run | Freezes PROMPT-007 without network; matches bare-letter MC0 scoring; keeps multi-token aggregation in SCORE/DEC-003 | PROMPT-007, CFG-006, REAL-001 | 2026-07-28 |
| DEC-011 | Multi-token candidate scoring aggregation | `multi_token_candidate_scoring="sum_log_probs"`: candidate score is the sum of conditional log-probabilities \(s=\sum_i \log p(t_i \mid \text{prompt}, t_{<i})\). No length normalization. No EOS token is included in the scored continuation (DEC-010). | (A) length-normalized mean log-prob; (B) official MC length-norm variant; (C) include EOS | Matches SCORE-007 test name and CFG placeholder; keeps aggregation explicit before SCORE-007 | SCORE-007, SCORE-008, CFG-006 | 2026-07-28 |

A decision is not frozen until its policy is explicit, validated in configuration, and covered by tests.
